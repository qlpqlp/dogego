# DIP-0037: BIP37 bloom filters (server + SPV client)

**Status:** implemented
**BIP:** BIP37
**Summary:** Core-compatible bloom filters for light clients: full-node server (`NODE_BLOOM`, `filterload`/`filteradd`/`filterclear`, `MSG_FILTERED_BLOCK` → `merkleblock` + matched txs, bloom-gated tx relay) and SPV client (wallet `filterload`, filtered-block sync, merkleblock ingest).

## Provenance

Wire format, murmur3 / `CBloomFilter` semantics, and SPV filtered-block flow follow **Bitcoin / Dogecoin Core** and the **libdogecoin** SPV path (`spvnode` filtering), including review and guidance from **[Ed Tubbs](https://github.com/edtubbs)** (libdogecoin / Dogecoin Foundation). DogeGo reimplements this in Go (no CGO link to libdogecoin) so Core and libdogecoin SPV clients can talk to a DogeGo full node the same way, and so DogeGo SPV mode can use bloom peers that do not advertise BIP157.

## What DogeGo does

### Shared (`bloom/`)

- MurmurHash3 and `CBloomFilter` insert/contains matching Bitcoin Core / BIP37
- Size caps: `MAX_BLOOM_FILTER_SIZE` 36000, `MAX_HASH_FUNCS` 50
- `nFlags`: `BLOOM_UPDATE_NONE` / `ALL` / `P2PUBKEY_ONLY` (relevant-tx match + outpoint update)
- Wire encode/parse for `filterload` / `filteradd`

### Full-node server

- Advertises `NODE_BLOOM` when running as a full node (`EffectiveP2PServices`)
- Per-peer filter state on primary + relay sessions
- `getdata(MSG_FILTERED_BLOCK)` serves `merkleblock` then matched `tx` messages (`wire.SerializeMerkleBlock`)
- Tx inv/relay honors peer `relaytxes` and bloom match
- Oversized / malformed filter messages increase misbehavior score

### SPV client

- When `FullNode=false` and the wallet is enabled, builds a bloom filter from tracked wallet scripts
- After handshake with `NODE_BLOOM` peers: sends `filterload`
- On block inv: requests `MSG_FILTERED_BLOCK` instead of full bodies
- Verifies inbound `merkleblock` against the header merkle root; ingests matched txs into wallet history (`IngestSPVMatchedTx`)
- BIP157 compact filters remain preferred when both peers support them; BIP37 covers Core / libdogecoin-era peers without BIP157

### Version `relaytxes`

- Still parsed from the BIP37 version bloom byte (unchanged)

## Out of scope

- Linking libdogecoin as a library
- Soft-fork / consensus changes
- Replacing BIP157 compact filter index
